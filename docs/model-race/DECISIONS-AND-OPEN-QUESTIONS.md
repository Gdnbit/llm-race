# 决策记录 / 假设 / 待解决问题（2026-10-24）

> 为后续 Coding Agent 保留这轮连续讨论的发展脉络。**讨论中的功能均为规划，不得无依据改称已实现。**

## ADR-001：不以通用模型数据库作为主产品

背景：LLM Race 最初通过 OpenRouter 与 LMArena 聚合模型元信息并通过 MCP 提供筛选/排序。扩大到图像、语音、视频等类别后，Models.dev、LiteLLM、Hugging Face、Artificial Analysis 及模型平台已有成熟部分。重复建设全量数据维护投入大，来源授权/时效/竞争问题复杂。

结论：**暂停以通用数据聚合、排行榜或独立模型目录平台为主的扩张**。保留历史代码。必要元数据通过合法第三方入口动态发现和缓存。

## ADR-002：将核心定位改为项目感知型多模态评测/选型 Skill

结论：开发者在已有项目中调用，Agent 先读现有代码、需求、业务样本和运行约束，再自主发现节点、匹配 Benchmark、执行真实测试和解释不同方案。支持 LLM、OCR、VLM、ASR、TTS、Embedding、Rerank、图像/音频/视频生成，并允许非模型路径。

## ADR-003：“数据源的数据源”是辅助参考，不是核心资产

结论：维护**来源发现方法、索引入口、来源质量核查规则、许可与适配器协议**，不以自建大数据库为先决条件。可以保留已验证端点和结果缓存，不追求海量抓取。

## ADR-004：多节点与系统级联合优化

结论：每个节点先独立评测，再测工作流端到端。自动产生至少两种有意义的不同方案，可按质量、速度、每成功任务成本、开放权重、自托管、稳定性、混合路由等目标生成；通过硬约束 + Pareto/多目标搜索筛选，避免“万能总分”。

## ADR-005：开发期与生产期均需建模

结论：分开核算实验调用、标注与执行成本，及生产 API/硬件/并发/重试/人工/运维的长期总成本。不把开发期便宜方案直接视为上线首选。

## ADR-006：Skill-first，复用而不是替代成熟评测生态

结论：Skill 承担项目理解、规划、决策、报告；复用成熟 Eval 框架完成真实评分，用轻量 Harness 保证权限、预算、缓存、追踪、任务恢复和可复现。先在 ThinkRoom 验证，再迁移到 ClassMatter。

## ADR-007：默认只建议，不擅自更换生产配置

结论：敏感数据出境、付费实验、读取私有资产、修改生产、提交代码/发布均有分层权限；产物可供 Coding Agent 生成开发分支变更，不自动部署。

## 未定事项（需实测/论证）

1. **名称与仓库**：公开名 Model Race 是否保留？是否重命名 `Gdnbit/llm-race`、沿用现有 MIT 许可证及如何处理外部链接/历史兼容？
2. **平台支持**：先支持 Codex、Claude Code 哪些平台的 Skill 结构和外部进程/网络权限？不同 Agent 的 background / resumed task 能力不能假定一致。
3. **自动节点识别**：如何识别动态工具调用、远程工作流、外部低代码平台、多个 Provider 代理？如何对“未发现的节点”作不确定性报告？
4. **授权预算**：默认实验运行需不需要主动授权？如何实现硬预算上限（部分供应商无法预先精确控制结算）？
5. **评测框架**：Promptfoo、Pydantic Evals、Inspect AI、EvalScope、AgentOpt、One-Eval、Agent-EvalKit 等的接口/许可/维护状况，需要有条件地复用，不预设全部依赖。
6. **置信度**：何时有足够的真实样本支撑推荐？没有人类真值的生成任务如何避免评审偏差？
7. **生产期推断**：如何要求用户输入日请求量、峰值、设备与人工成本、复杂度分布；参数未知时如何输出范围与敏感性分析？
8. **跨节点联合搜索**：何时值得优化动态路由/回退链，如何限制组合爆炸及额外路由成本？
9. **公开发布安全性**：包含用户项目结构、私有需求或运行 Trace 的产物默认本地、私有；开源仓库中仅发布示例/合成结果。
10. **证明价值**：与“直接让 Coding Agent 临时调研并写脚本”相比，Skill 是否显著降低人工时间、成本并减少错误？要做 A/B 或成对任务比较。

## 优先实验与否定条件

- **先做：** ThinkRoom 两到三个节点的完整 Project → Eval → 多方案报告闭环；随后 ClassMatter 的不同性质节点迁移。
- **暂不做：** 自建海量模型库、公开排行榜、独立 Web 管理后台、任意模态全覆盖、生产自动切换、对所有第三方站点全量抓取。
- **可否决条件：** 若复用现有工具的 Coding Agent 无需这个 Skill 已能稳定、低成本、合规完成同样工作，或者 Skill 只增加流程复杂度却不提升可信度，应减少项目范围或暂停独立开发。

每项开放问题应补充：验证日期、来源链接、可复现测试命令、样本量/范围、结果、限制、负责人或下次行动。决策变更请新增 ADR，不要静默覆盖历史结论。
