# 03 · 数据源发现、数据质量与可复现评测方法

> **设计草案：独立数据来源、公开 Benchmark 与本项目测评数据必须区分。** 本文件不代表仓库已下载/拥有任何受限评测数据或测出任何得分。

## 1. 核心决定：维护“源发现能力”，不维护世界数据库

用户提出的“数据源的数据源”仅是 **Skill 内置资源的一层**。维护少量可靠的**发现入口及方法**，由 Agent 面向当下节点和版本动态定位准确、合法、最新的实际资料。

四类入口：

| 层次 | 例子 | 价值 | 必要核对 |
| --- | --- | --- | --- |
| 模型/端点索引 | Models.dev、LiteLLM 模型价格表、Hugging Face Hub、OpenRouter、Replicate、fal.ai | 候选发现、能力/部署/价格初筛 | 模型身份、Provider 版本、时效、来源许可 |
| 评测发现入口 | 官方 Benchmark 目录、EvalScope/Inspect AI 数据集目录、论文/评测索引 | 定位适合的公开测试任务和数据 | 指标含义、训练污染、数据集许可 |
| 原始权威资料 | 服务商官方定价和 API 文档、模型卡、原始论文、原始评测报告 | 核验关键结论 | 发布/变更时间、适用区域、版本、样本、协议 |
| 用户项目实证 | 测试案例、已标注业务样本、运行 Trace、人工验收/故障单 | 判断真实业务表现 | 数据授权、脱敏、代表性、标注可靠性 |

**信息发现源 ≠ 证据原始源**。两个聚合网站转述同一张第三方榜单，不构成两份独立证据。优先追溯原始声明与评测方法。

Source Registry 可仅储存入口 URL、任务覆盖、检索方法、更新检测、许可/访问说明与可信性检查规则；无需复制第三方模型数据库。可信来源变化时动态发现，Agent 可建议加入 Registry；实际采集/再发布前核查 ToS、限速、版权和使用条款。

## 2. 来源事实的分级与元数据

推荐统一证据层级：

- `PROJECT_MEASURED`：当前项目固定环境、受控实验中实测；提供输入、评估器、样本量、运行日志与误差。
- `EXTERNAL_BENCHMARK`：外部公开评测；记录原始链接、任务、版本、评估协议、数据覆盖，不能推断为本项目表现。
- `PROVIDER_CLAIM`：服务商模型卡、宣传、价格、规格；注明未独立验证。
- `INFERRED`：基于已有描述/规则推断；必须附推断条件，禁止当实测。

字段建议：`source_url`、`retrieved_at`、`published_at`、`model_version`、`endpoint_version`、`pricing_region`、`dataset_version`、`metric_name`/`unit`/`direction`、`eval_method`、`license`、`confidence`、`staleness`、`known_limitations`。

**缺失的数据是 unknown，不是 0，也不是通过默认模型填满。** 对版本不匹配、发布时间太旧、互相矛盾或置信度不高的资料做 flag；必要时暂停决策。

## 3. 项目数据优先，合理使用公开 Benchmark

### 3.1 真实业务样本

优先使用用户已有的经授权、已标注项目案例。分析：

- **来源和合法性**：用户是否有权让 Skill 读取、复制、脱敏、调用外部 API？学生、患者、合同、客户财务等必须严格审查。
- **样本有效性**：输出是否有人工真值，还是历史模型自己的回答？避免“拿旧模型回答当标准答案”的自我循环。
- **分布**：是否代表现实请求，覆盖长短文本、文档模糊度/质量、不同语言、格式、异常输入、边界/对抗场景和高风险类别。
- **标注质量**：多个评审分歧、字段规范、模糊题和可接受答案集合；必要时双人审查/仲裁。
- **切分**：用于开发与 Prompt 调优的样本不得与最终保留评测集混同；按用户/文档/模板、时间等独立性合理分组，避免泄漏。

### 3.2 公共测试集

用于补全任务能力、输入长尾和通用对比；但公开排名不能替代项目测试。检查：Benchmark 来源、语言/地域、数据构建、许可、下载与缓存合法性、格式和评判器、答案污染、样本难度与真实输入差异。

**典型任务发现线索（不是已集成声明）**：

- 文档 OCR / VLM：EvalScope 内的 Doc/OCR 类型任务目录、OCRBench、DocVQA、OmniDocBench 等；需检查任务适配、版本及许可。
- ASR：Common Voice、FLEURS 之类的开放语音测试；按语种/口音/噪声区分、查阅具体许可。
- LLM/Agent：工具调用、结构化提取、引用正确性、真实项目测试集，必要时参考 BFCL 等协议；不要将通用推理榜单直接当 Agent 成功率。
- 生图/视频/TTS：参照成熟的人评/自动打分协议，必要时人工双盲评；避免以单一模型 Judge 作为唯一真值。
- Embedding/Rerank：在真实检索语料上测 Recall@K、MRR、NDCG、下游问答正确率及代价；可参考相关公开检索基准。

## 4. 任务专用指标字典

| 任务 | 核心质量指标（按业务适配） | 性能/资源指标 | 特殊风险 |
| --- | --- | --- | --- |
| 结构化 LLM 抽取 | 精确字段正确率、漏提/误提、格式合规、严重错误率 | Token、P50/P95、重试后成本 | 伪造字段、错误输入传播 |
| 文档问答/证据 | 引用可追溯率、答非所问/无证据拒答、业务有效性 | 上下文、延迟、RAG 调用费用 | 引用错位、幻觉、泄露 |
| Agent/tool use | 任务成功率、工具调用有效率、权限违规率、回滚率 | 总步骤、端到端成本与时间 | 越权写操作、非幂等副作用 |
| OCR/扫描文档 | CER/WER、版面/表格结构、关键字段准确率 | 页/秒、单页成本、内存 | 图像失真、表格重排 |
| 图像理解/VLM | 实体/关系/图表准确率、指令遵循度 | 分辨率、视觉 token、P95 | 幻觉、局部细节遗漏 |
| ASR | CER/WER、关键词正确率、端点检测、时间戳准确率 | 实时因子 RTF、首包/P95、RAM | 噪声、口音、重叠说话者 |
| TTS/音频生成 | MOS/人工自然度、可懂度、发音、韵律 | 首包延迟、秒/字符成本 | 评审偏差、授权/肖像声音 |
| 图片生成/编辑 | 提示遵循、结构一致性、可编辑性、人工盲评胜率 | 张/次成本、生成耗时、失败率 | 主观评分、输出版权/安全 |
| 视频生成/理解 | 时间一致性、指令遵循、视觉质量、任务准确率 | 秒/片成本、吞吐和 P95 | 时长/分辨率差异影响价格 |
| Embedding/Rerank | Recall@K、NDCG@K、MRR、业务端到端准确率 | 向量维度/存储、查询 P95/成本 | 数据泄漏、索引重建成本 |

**指标是候选字典，不是每个节点都测全部。** 例如 OCR 的 CER 很好但合同关键金额字段不对，业务上仍是不合格；生成质量主观指标必须报告 Judge/人工评审方法和一致性。

## 5. 输入质量与数据分层

用户特别强调输入数据集质量。建议 Agent 先形成 `input_profile`：

- 类型/模态/格式/来源比例；扫描 vs 数字 PDF；中文/英文及混合；
- 文本长度、长尾长度、表格密度、图像分辨率/模糊度/倾斜、音频信噪比/口音/说话人数；
- 数据缺失、解析异常、隐私标记、标签可信度、与未来生产可能的分布偏差；
- 已有样本少于业务情境所需时，输出“覆盖缺口”和优先标注建议。

每个报告应有**分层结果**：简单/中等/困难、主流/长尾、高风险样本，而非单个平均分。避免把少量清晰文档上的表现外推到大量模糊照片。

## 6. 实验流程与有效性

1. **明确决策与预算**：要回答什么问题，最低合格标准为何，付费上限和停止条件是什么。
2. **固定条件**：数据集版本/拆分、Prompt、解析器、模型与 endpoint 版本、服务商地区、温度/采样、重试和缓存策略。
3. **基线 + 小样本试跑**：已有方案必须入选；先测少量且有代表性的样本验证 SDK、评判规则与费用估算。
4. **阶段化筛选**：剔除硬约束不符或明显不合理的候选，再扩大样本、重复抽样/并行对照；昂贵候选有限额。
5. **评估不确定性**：样本数、按分层的误差、bootstrap 区间或其他适合的估计；样本太少标记 `insufficient_evidence`。
6. **节点级 → 端到端**：保留上游/下游兼容性，观察格式变化、重试和错误累积。
7. **压力和故障测试**：生产候选补充并发、超时、限速、断网、fallback、权限/数据越界、资源耗尽。
8. **结果可重跑**：保存数据版本或合法哈希、模型 endpoint 和版本、测试代码版本、参数、运行成本与摘要。
9. **区分发现与验证**：Agent 搜索到资料 != 已完成实测；缓存已有实测要标识执行时间、样本适用性和代码版本。

### 6.1 LLM-as-Judge 的限制

可用于开放式回答或主观创作辅助评审，但必须记录 Judge 版本/提示词/采样、尽量对候选匿名盲评、检查位置偏见和分数偏差，选取人工标注案例校准。对于有确定标准答案的结构化任务，优先使用确定性评价器；高风险结果不由单一 Judge 独断。

## 7. 统一成本计量

**不同模态价格不能强行都换算成每 1M Token。** 使用单位化 cost ledger：

- 文字：输入/输出 token、缓存 token、长上下文附加收费、批处理/推理模式。
- OCR/文档：页/请求/文档、图片尺寸、解析器成本。
- ASR/TTS：音频秒/分钟、字符、流式服务、声线附加费用。
- 生图/视频：张/次、分辨率/步骤、生成秒数/视频时长、失败重试。
- 自托管：GPU/CPU 小时、RAM/VRAM、负载率、存储、运维、设备摊销。
- 人工：标注、复核、异常处置、维护时间。

关键指标建议：`cost_per_successful_task = total_cost / number_of_accepted_business_tasks`，同时报告失败率、是否计入人力、样本数及时间窗。总请求成本并不等于真实完成业务成本。

## 8. 安全与授权规则

- 用户私有样本默认本地只读；脱敏不是免授权，保留审计轨迹；未经许可不得发到第三方 API。
- 不应将 API Key、Prompt 中的私密资料、客户合同、学生/医疗记录、完整 Trace 作为公开仓库测试夹具。
- 数据下载/再分发检查许可和条款；第三方 Benchmark 原始资料可链接和按条件本地下载，不无授权镜像发布。
- 模型候选调用必须有实付限额和接口速率限制、预估最大消耗、错误/停止条件；估算不准确时保守停止。
- 生成测试不能直接触发发邮件、审批、转账或修改业务事实等有副作用的工具；需要 mock、隔离或人审。
- 不能把通过自动化测试解释为合规法律结论、SLA 承诺或上线批准。
