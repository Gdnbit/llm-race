# Model Race · 项目感知的多模态模型评测与选型 Skill

> **文档状态：2026-10-24 产品方向与开发规划（proposed / 未实现）；不等同于仓库当前功能。**
>
> 仓库现名为 `llm-race`，历史实现是 OpenRouter + LMArena 数据管线、模型归一化、启发式评分和三个 MCP 工具。尚未实现本文所述的项目自动扫描、跨模态实测、系统级组合优化或生产成本预测。历史代码请参见 [根目录 DESIGN.md](../../DESIGN.md)。

## 一句话定义

**Model Race 是供 Coding Agent 调用的项目感知型、多模态、多节点自动评测与选型 Skill。** Agent 先理解用户现有项目的业务目标、开发进度、部署环境、输入数据及模型调用链；然后对每个 AI/模型节点动态确定硬约束和评价标准，发现适合的候选技术方案与可用测试集，运行受控、可复现的实测；最终面向开发测试期和正式生产期分别输出多套系统级方案，并清晰解释质量、速度、成本、可靠性、隐私和维护上的取舍。

**不是**新的全球 AI 模型数据库、固定榜单、纯价格比较器、单模型推荐 Prompt，也不是必须重新开发一个大平台。

## 从本轮讨论确认的决定

1. **Project-first / Node-specific**：先研究真实项目，再判断节点需要哪些维度和测试。不同节点不得共用僵硬的万能权重。
2. **多模态、多任务**：不仅 LLM，也覆盖 OCR、VLM、ASR、TTS、图像/音频/视频生成、Embedding/Rerank 等；可以选非模型技术。
3. **数据源的“数据源”是辅助资源**：内置的是来源发现入口、可信度规则、检索方法和评测配方；不维护全量模型价格或全量 Benchmark 复刻库。
4. **用户现有证据优先**：优先复用已标注的项目业务案例、测试/Trace；公开 Benchmark 用于补充，不可替代对真实任务的检验。
5. **多目标、多方案**：不是给唯一排行榜第一名；输出质量、速度、性价比、私有化、开放权重、稳定可靠、混合配置等方案，并附适用条件。
6. **节点级 + 端到端**：节点高分不代表整条工作流更优，需验证错误传播、系统完成率和总体成本。
7. **开发期与生产期分开考虑**：开发评测预算和生产长期 TCO、并发、故障恢复、数据合规及迁移风险必须分别建模。
8. **自动化而不失控**：Agent 可自主调查、生成与执行测试；外部敏感数据、付费预算、部署替换需要明确授权。
9. **Skill-first, Harness-backed**：Skill 协调流程，优先复用成熟评测框架；执行层保证预算、日志、缓存、断点恢复和可复现性。
10. **有证据才声称有效**：将推测、第三方指标和本项目独立实测严格分开；不把建议/规划写成已实现。

## 当前仓库与未来方向的关系

- **当前已实现（截至检查）：** `data-pipeline` 中的模型元数据采集（OpenRouter 主数据、LMArena 补充）、跨来源模型名称对齐、Pydantic 契约与本地 JSON 导出；`mcp-server` 中的 `list_models`、`get_model`、`recommend_for_pipeline_step`。
- **尚未实现：** 自动理解任意用户项目、跨模态测试集发现、节点分类、业务数据分层、真实 API 对照实验、系统配置 Pareto 搜索、开发/生产双成本报告、可安装的 Model Race Skill。
- **转型方案：** 不必删除原来的代码；保留数据管线和 MCP 作为可选能力或参考，先用实际项目验证新形态，再决定复用、拆分、废弃或仓库改名。**不在这次纯文档更新中修改任何运行时代码或对外产品承诺。**
- **术语：** Model Race 为暂定对外名，`llm-race` 是当前真实仓库路径；是否正式重命名，另行评估迁移成本。

## 后续开发者的第一步

阅读本文全部文档并检查当前代码、测试和最新依赖；先记录“事实 vs 规划”的差异，再选择 [路线图](06-ROADMAP-AND-ACCEPTANCE.md) 的最小验证实验。不要凭这些文档认定代码存在、模型已跑分、生产效果已验证或者已有客户付费。

## 非目标

无授权抓取或再分发第三方受限数据；将客户敏感资料自动上传外部服务；无标准答案却编造“准确率”；无成本上限自动调用付费 API；在未确认的情况下修改生产模型；为了做通用排行榜而维护无限增长的数据集。
